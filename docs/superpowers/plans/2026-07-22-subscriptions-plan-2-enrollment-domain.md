# Level Subscriptions — Plan 2: Enrollment Domain Implementation Plan

> **For agentic workers:** Use superpowers:executing-plans / subagent-driven-development. Steps use checkbox (`- [ ]`) syntax.

**Goal:** Model a learner's annual enrollment into a level (holding one capacity slot per swim year) and the per-term payments that bill it, with a service that creates enrollments, enforces capacity, and activates on payment — no payment gateway yet.

**Architecture:** Two tables. `enrollments` = (learner, level, swim_year) holding one capacity slot for the year; `term_payments` = one pending row per term of that year. `EnrollmentService.enroll(...)` validates availability/school/duplicates, resolves the per-term price (school fee override → level default), enforces `level.capacity` against active + live-pending enrollments inside a locked transaction, and creates the enrollment + a payment per term. `markTermPaymentSucceeded(...)` (called later by the Paystack webhook) flips a payment to success and activates its enrollment.

**Tech Stack:** AdonisJS 7, Lucid 22, VineJS, Japa unit tests, better-sqlite3. Money in pesewas (integers).

## Global Constraints

- Prefix commands with `mise exec -- ` (Node 26 via mise).
- Enum-like values as string `as const` objects in `app/values/` (mirror `app/values/level_audience.ts`), validated/compared as strings.
- Money in minor units (pesewas) as integers; currency string `'GHS'`. Price is the **per-term** amount, captured (frozen) on the enrollment and each term payment at enroll time.
- `public_id` UUIDs on new tables, generated by a `@beforeCreate` hook (mirror `app/models/program.ts`).
- Commit `database/schema.ts` after each migration. Row locks via `.forUpdate()` through the trx (SQLite serializes writes; the lock is a portability no-op there).
- No HTTP/controllers/UI in this plan — the public purchase flow is Plan 4. This plan is the domain + service, unit-tested.

### Task 5: `EnrollmentService.enroll` — creation + per-term payments

**Files:** Create `app/services/enrollment_service.ts`; test `tests/unit/enrollments/enroll.spec.ts`.

**Produces:** `enroll(school, { learnerId, levelId, swimYearId }): Promise<Enrollment>` — creates a pending enrollment (price = school fee override ?? level.defaultFee) plus one pending `TermPayment` per term of the swim year, in a transaction.

- [ ] **Step 1: Test (happy path)** — seed school + curriculum + swim year (2 terms) + a learner (via a signup for the school), call `enroll`, assert: enrollment status `pending`, price == level.defaultFee, currency `GHS`, `reservedUntil` set; two `term_payments` created, each amount == price, status `pending`.

- [ ] **Step 2: Implement `enroll`** — resolution + rules:
  - Load level with `schoolLevelSettings` (school-scoped) + `program`; throw `EnrollmentException('This level is not available.')` if program inactive or setting.available === false.
  - Load swim year (where schoolId) with terms ordered by position; throw if not found or `status === 'archived'`.
  - Load learner; throw `EnrollmentException('Learner not found for this school.')` if its signup's schoolId ≠ school.id (join learners→signups).
  - Reject duplicates: existing enrollment for (learnerId, levelId, swimYearId) with status in (`pending` with reservedUntil > now, `active`) → throw `'Already enrolled for this year.'`.
  - price = `setting?.fee ?? level.defaultFee`.
  - In `db.transaction`: capacity check (Task 7 adds enforcement — Step here creates the enrollment + payments). Create enrollment (status pending, price, currency 'GHS', reservedUntil = DateTime.now().plus({ minutes: 30 })). Create a term_payment per term (amount price, currency, status pending).
  - Return enrollment.

- [ ] **Step 3:** Run the test → PASS. Commit.
